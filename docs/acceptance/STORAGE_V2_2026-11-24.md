# Storage-v2 development validation — 2026-11-24

## Scope and baseline

This report covers the incompatible storage-format update based on MiniSQL
commit `7fdab6bd49e8ac344632528109efd7e06e635afd`. The requested changes are binary
REAL/DOUBLE storage, aligned rows, a mandatory table metadata page 0, U32 overflow
lengths, and little-endian numeric SQL index components with semantic ordering.
See [the format overview](../formats/storage-v2.md) for the persisted contract.

Validation used MiniLang Compiler 1.3.10, compiler source commit
`8e64c9cfda92199b68ac5d3974fea445f12f6c39`, with native Linux x64 executables.
Test fixtures were isolated under ignored `build/` directories. Existing
databases were not converted or used as mutable fixtures.

## Focused binary-format gate

All five suites passed after the final SQL conversion and index corrections.

The internal cross-platform runner is exposed through `test.ps1 -StorageV2`.
The native Linux invocation is:

```sh
python tests/run_storage_v2.py --target linux-x64 --compiler ../MiniLangCompilerPy/mlc_win64.py
```

| Suite | Coverage |
|---|---|
| `storage_v2_metadata` | Metadata byte goldens, exact version tuple, old versions, mixed versions, flags and reserved fields |
| `storage_v2_rows` | IEEE-754 goldens, 128 finite bit patterns, signed zero, subnormals, natural alignment, zero padding, malformed rows, slot bounds/overlap and failure atomicity |
| `storage_v2_table` | Exact page-0 metadata, first data page 1, immutable header after growth, corruption, all physical open modes and legacy rejection |
| `storage_v2_overflow` | U32 boundary without allocating 4 GiB, independent pointer CRC golden, reserved bytes, damaged/truncated pointers and legacy rejection |
| `storage_v2_indexes` | I64 limits, 255/256, finite floating order, escaped/composite keys, uniqueness, splitting/ranges/reopen, covering results and signed-zero SQL conversions |

The runner writes per-test compiler/runtime logs and machine-readable
`results.json`. A native pass requires both exit status 0 and the test's exact
success banner. Cross-compilation is explicitly recorded as `COMPILE_PASS` and
does not count as native execution.

## Signed-zero regression found during review

The strengthened index test first reproduced loss of `-0.0` in a DOUBLE key, a
REAL key and an INCLUDE value before the index was built. SQL numeric promotion
and text conversion discarded the sign before row serialization. A second
reviewed path reconstructed a covered equality key from the search literal,
which cannot preserve the stored value's sign.

The correction preserves floating inputs during conversion, restores a negative
zero sign for explicitly negative zero text, retains stored key bits, and reads
actual B+ tree entries for covered equality scans. The numeric comparator treats
both zero signs as equal; transient byte-hashed constraint keys normalize them.
The regression checks range and equality scans, composite equality, INCLUDE,
uniqueness and reopening against the heap's original binary64 bytes.
