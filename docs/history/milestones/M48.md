# M48 acceptance candidate — continuous hot replication

M48 introduces:

- a CRC-32C protected `wal.log.durable` sidecar containing the WAL prefix known
  to have completed the data-file flush;
- live archive export that reads only this durable prefix while the primary
  remains open;
- strict prefix continuity and record-boundary validation;
- a read-only standby server mode;
- a Python controller that alternates two fully materialized standby slots and
  switches new loopback client connections only after recovery succeeds.

Acceptance requires both the direct MiniLang durability/standby test and a
public-process integration test using `minisqld.exe`, `minisql.exe`,
`minisql-backup.exe` and `minisql_hot_replica.py`.
