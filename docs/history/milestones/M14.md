# M14 acceptance candidate R1 — transactional DDL

M14 validates atomic CREATE TABLE, CREATE INDEX and DROP TABLE operations. The test
checks persisted column rules, identity/default metadata, primary/unique/check and
self-referencing foreign-key constraints, physical table/index files, explicit rollback
and recovery of a prepared DDL journal after a simulated process stop between file
publication and catalog publication.

DDL uses before-images and a durable journal. A PREPARED journal is rolled back before
the database opens; a COMMITTED journal is cleaned without undoing the new schema.


The initial Windows candidate failed before its first DDL commit because before-image
capture reopened `db.meta` and `catalog.tbl` while the active database handle held
exclusive whole-file locks. R1 snapshots those bytes through the owner handles and adds
a static recurrence guard. The persisted DDL journal format is unchanged.
