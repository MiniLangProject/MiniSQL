# M5 acceptance contract

Status: **accepted by the cumulative M2–M5R2 Windows result (19/19 phases PASS)**.

Acceptance is performed by the single cumulative `test.ps1` M0-M5 gate.

M5 introduces a fixed-capacity buffer pool with explicit page guards, pin counts, dirty
tracking, synchronous dirty-page flush and CLOCK replacement.

Acceptance includes M2 through M4 and requires:

- repeated pins of the same page to hit the resident frame;
- refusal to evict when every frame is pinned;
- second-chance CLOCK eviction after guards are released;
- dirty-page resealing and persistence;
- rejection of double release and close while pinned;
- capacity and statistics invariants;
- deterministic multi-page stress with a reference model;
- a 71-module M5 smoke program; and
- exit code 0 with final line `MiniSQL M2-M5 acceptance test: SUCCESS`.

## Safety boundary

M5 is not yet a transactional durability release. WAL, atomic commit, checkpointing and startup recovery remain M6-M7. No irreplaceable data may be entrusted to this build.
